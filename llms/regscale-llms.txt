# RegScale Documentation

> Streamline your governance, risk, and compliance (GRC) processes with RegScale’s modern platform for shift-left security and compliance as code. RegScale’s Continuous Controls Monitoring (CCM) platform helps organizations stay audit-ready by continuously updating documentation and compliance artifacts in real time. Built as a cloud-native solution with full support for hybrid and on-premises environments, RegScale integrates seamlessly into your CI/CD pipelines—speeding up certification, reducing manual work, and lowering costs.

Append .md to any documentation page URL to get its markdown version.

## Guides
- [General](https://regscale.readme.io/docs/setup-general.md): The General section contains high-level tenant configuration settings and license information. Administrators can customize the look and feel of the platform and manage key branding options.
- [Classification](https://regscale.readme.io/docs/setup-classification.md): The Classification section allows you to define categories with associated confidentiality, integrity, and availability (CIA) values. These are commonly used in system categorization and risk workflows.
- [Compliance Settings](https://regscale.readme.io/docs/compliance-settings.md): Compliance Settings let you complete compliance activities using each framework’s native language. With Compliance Rollup, you can report across multiple frameworks while preserving their unique taxonomies.
- [Email Settings](https://regscale.readme.io/docs/email.md): RegScale supports integration with customer email systems using SMTP. Email configuration is required for user registration workflows and for sending alerts across the system.
- [Single Sign-On (SSO)](https://regscale.readme.io/docs/setup-single-sign-on-sso.md): This guide describes how to configure Single Sign-On (SSO) for RegScale using industry-standard authentication protocols. It includes setup instructions for OAuth (including Azure AD and Okta) and SAML configurations.  SSO allows users to sign in to RegScale using credentials from a centralized Identity and Access Management (IAM) solution. This enables centralized user management, support for Multi-Factor Authentication (MFA), integration with enterprise authentication monitoring tools, and improved security through adaptive authentication methods.  RegScale supports both OAuth 2.0 and SAML for SSO.
- [Theming and Branding](https://regscale.readme.io/docs/setup-theming-and-branding.md): Theming and branding allow partners and customers to set up RegScale to match their organization’s identity. These features enable quick deployment of branded compliance platforms without requiring code changes. Common use cases include managed security service providers (MSSPs), system integrators (SIs), and cyber advisory firms delivering consistent, tailored user experiences while maintaining control over visual presentation.
- [Setup User Management and Roles](https://regscale.readme.io/docs/identity-and-access-management.md): RegScale offers flexible tools for managing users, groups, and roles to align access with your organizational needs.
- [Multi-Factor Authentication (MFA)](https://regscale.readme.io/docs/multi-factor-authentication-mfa.md)
- [Security Policies](https://regscale.readme.io/docs/setup-security-policies.md): RegScale offers configurable security policies to align with your organization’s risk tolerance and user experience requirements. While secure by default, administrators can further tailor settings using the built-in policy engine.
- [Cause Codes](https://regscale.readme.io/docs/setup-cause-codes.md): Cause Codes allow you to define standardized codes for use in the Causal Analysis module. These codes help categorize and trace the root causes of issues across your organization.
- [Facilities](https://regscale.readme.io/docs/setup-facilities.md): The Facilities section (Facility Manager) allows administrators to define physical locations for use across modules. Once added, facilities can be linked to module records via the Basic Info section under Data Entry.
- [File System](https://regscale.readme.io/docs/setup-file-system.md): The File System Config section defines upload limits and acceptable file types across the platform.
- [Functional Roles](https://regscale.readme.io/docs/functional-roles.md): The Functional Role Manager allows you to define named roles that can be reused in workflows for routing, notifications, and approvals.
- [Modules and Features](https://regscale.readme.io/docs/setup-modules-and-features.md): The Modules and Features section allows administrators to enable or disable platform modules and RegScale feature flags based on organizational needs.
- [Risk Model](https://regscale.readme.io/docs/setup-risk-configuration.md): Risk Configuration allows administrators to define custom risk and opportunity models, configure scoring logic, and tailor assessment criteria based on organizational standards.
- [Tags](https://regscale.readme.io/docs/setup-tags.md): The Tag Manager allows administrators to create and manage tags for organizing files and enabling OSCAL-compatible exports. RegScale includes a predefined set of system tags to support FedRAMP and other compliance frameworks.
- [Service Accounts](https://regscale.readme.io/docs/service-accounts-1.md): Service accounts allow administrators to generate Personal Access Tokens (PATs) for automated, programmatic access to RegScale APIs.

- [Builder Utility](https://regscale.readme.io/docs/builders.md): The Builder utility simplifies adding Control Implementations and Requirements by applying Security Profiles and Catalogs. Use it to quickly populate Security Plans, Projects, Policies, and Supply Chain records—ensuring speed, consistency, and reduced manual effort.
- [Inheritance Utility](https://regscale.readme.io/docs/inheritance.md): The Inheritance utility provides the ability to inherit Control Implementations from an existing Security Plan or Policy. This streamlines control reuse across systems and components, minimizing manual effort and accelerating compliance.  Use inheritance to tier systems (e.g., components under a system-level Security Plan), reduce redundant work, and align with cloud compliance models like FedRAMP.
- [Categorization Utility](https://regscale.readme.io/docs/categorization.md): The Categorization utility dynamically applies controls to Security Plans or Components based on structured assessments. It supports a risk-based approach aligned with NIST RMF Steps 1 and 2 (Categorize and Select Controls).  Use Categorization to automate control selection, reduce manual effort, and improve consistency in system authorization packages.
- [Deviations Utility](https://regscale.readme.io/docs/deviations.md): The Deviations utility supports the FedRAMP deviation process by managing exceptions to standard security controls. It helps document and justify non-compliance due to technical or business constraints, enabling secure and authorized exceptions within cloud environments.  Use this utility to automate deviation handling, link directly to issues and POAMs, and streamline FedRAMP reporting.
- [Date Extension Requests Utility](https://regscale.readme.io/docs/date-extension-requests.md): The Date Extension Request utility allows users to request revised due dates for Assessments, Issues, or Tasks that require more time to complete. It supports formal workflows for justification and approval, ensuring auditability and accountability in the extension process.
- [Recurrence Utility](https://regscale.readme.io/docs/scheduling.md): The Recurrence Utility automates the scheduling of recurring items such as Assessments, Data Calls, and Corrective Action Tasks. Use it to reduce manual effort and ensure deadlines are met consistently.
- [Control Mapping Utility](https://regscale.readme.io/docs/transformer.md): The Control Mapping Utility provides organizations the ability to map controls between catalogues, enabling reuse of assessment data across multiple frameworks. This reduces redundant work and simplifies the creation of crosswalked SSPs (e.g., NIST to ISO).  Use it to create a single Security Plan or Assessment against one standard, and automatically align with controls from other mapped standards.
- [Subsystems](https://regscale.readme.io/docs/subsystems.md): Subsystems are standardized features available across all RegScale modules. They support collaboration, tracking, classification, relationships, and other key functions tied to a specific record.
- [Comments Subsystem](https://regscale.readme.io/docs/mentions.md): The Comment Subsystem allows users to post messages directly on any record across modules. It’s available in the  Subsystem section of every record.
- [Files Subsystem](https://regscale.readme.io/docs/files.md): The File Subsystem allows users to upload, manage, and organize files on any record. It is available under the Subsystem section of each module.
- [Links Subsystem](https://regscale.readme.io/docs/links-subsystem.md): The  Links Subsystem allows users to associate external or internal URLs with a specific record. This enables quick access to related systems, documentation, or resources directly from within RegScale.
- [Kanban Subsystem](https://regscale.readme.io/docs/kanban-subsystem.md)
- [History Subsystem](https://regscale.readme.io/docs/history.md): The History Subsystem provides an audit log of all actions taken on a record, including views, edits, comments, prints, and emails.
- [Workflow Subsystem](https://regscale.readme.io/docs/workflow-subsystem.md): The  Workflow Subsystem allows you to start or build approval workflows directly from a record. Workflows can follow predefined paths or be created on demand.
- [Classification Subsystem](https://regscale.readme.io/docs/classification.md): The Classification Subsystem allows users to apply and manage data classification values on a record, including confidentiality, integrity, and availability levels.
- [Time Travel Subsystem](https://regscale.readme.io/docs/time-travel.md): The Time Travel Subsystem provides a cryptographically linked version history for each record, enabling users to view, validate, and revert changes over time. Each save creates an encrypted snapshot.
- [Timeline Subsystem](https://regscale.readme.io/docs/timeline.md): The Timeline Subsystem allows users to record and visualize key events associated with a record.
- [Relationship Subsystem](https://regscale.readme.io/docs/relationship-manager.md): The Relationship Subsystem allows users to create many-to-many links between records across modules. These connections enhance context, support AI features, and improve data modeling across the platform.
- [Stakeholders Subsystem](https://regscale.readme.io/docs/stakeholders-subsystem.md): The Stakeholders Subsystem allows you to associate people or organizations with a record for accountability and communication.
- [Properties Subsystem](https://regscale.readme.io/docs/properties-subsystem.md): The Properties Subsystem allows users to define key-value pairs on a record for storing custom metadata.
- [Data Subsystem](https://regscale.readme.io/docs/data-subsystem.md): The Data Subsystem allows users to attach structured or unstructured data objects to a record using raw code input.
